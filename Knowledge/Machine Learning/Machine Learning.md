The root of the machine learning domain. Everything under `Knowledge/Machine Learning/` hangs off this note. Its job is to hold the definitions the rest of the vault leans on, and to name the areas so nothing gets filed by accident.

> [!quote] Definition(s)
>Machine learning is the science (and art) of programming computers so they can learn from data. ~[[HOML Ch01 The Machine Learning Landscape|HOML Chapter 1]]
>
>Machine Learning is the field of study that gives computers the ability to learn without being explicitly programmed. ~Arthur Samuel, 1959
> 
>A computer program is said to learn from experience $E$ with respect to some task $T$ and some performance measure $P$, if its performance on $T$, as measured by $P$, improves with experience $E$. ~Tom Mitchell, 1977
>
>Machine learning is an approach to learn complex patterns from existing data and use these patterns to make predictions on unseen data ~[[DMLS Ch01 Overview of Machine Learning Systems|DMLS Chapter 1]]





Mitchell's $E$, $T$ and $P$ are the three hooks the rest of the domain hangs on: $E$ is the [[Training Set]], $T$ is one of the tasks listed under Areas below, and $P$ is the [[Performance Measure]].

What none of those three settles is when the word applies at all, and that separate question is held by [[Machine Learning Applicability]], the conditions a problem has to meet before machine learning is the right tool for it: five that decide whether the approach can work, and four that decide whether it is worth paying for.

## Areas

- **`_Foundations/`** the framework-independent vocabulary every other note assumes. [[Model]] is the thing that learns and then predicts, a function from a feature vector to an output together with the parameters set during training; [[Feature]] is one column of the data that function reads; [[Hyperparameter]] is a setting of the learning algorithm rather than of the model, fixed before training and unchanged by it; and [[Training Set]] and [[Training Instance]] are the data fitted on and one row of it. Four notes sit around the rest rather than beside them, and they run in order. [[Machine Learning Applicability]] is the gate in front of everything, nine conditions checked before a project starts, five of them necessary and four of them deciding whether the investment pays, so a problem can be ruled out before anyone collects data or buys hardware. [[Machine Learning System]] is what gets built once that gate opens, and it is not the model: it is the code, the training data, and the artifact fitted from the two, whose deployed behaviour depends on all three jointly, which is why two deployments running byte-identical code can behave differently. [[Machine Learning Systems Design]] is the activity of deciding what that system has to do and of checking that it does, considering the system whole so that its components and everyone with a stake in it together satisfy what was actually asked of it, and it is where the four requirements sit: reliability, scalability and maintainability in the form a system fitted from data gives them, and adaptability, which is fourth because no general requirement covers a data distribution that shifts underneath a model that does not. Those four are requirements rather than properties a design has or lacks, since they trade against one another, and the sharp instance is the last against the first, adaptability asking for frequent updates and reliability for a system that does not change underneath you, so the update cadence is a number negotiated between them rather than maximized. The same note is where the several-objectives problem is settled, how many objectives a system has and how they are to be combined, decided before there is anything to fit. [[Machine Learning Project Lifecycle]] is the shape the work takes, six phases running from project scoping through data engineering, model development, deployment, monitoring and continual learning, and business analysis, whose sixth returns to the first, so no phase is terminal and a project's state is a position in a cycle rather than a percentage of completion. Its structural claim is about which phases feed back into which: the eight back edges are exactly the complete bipartite connection between the two phases that learn something from a running system, monitoring and business analysis, and the two that build one, data engineering and model development. Feedback is therefore not a general licence for any phase to send you back to any other, deployment is a pass-through that no back edge reaches, and project scoping is arrived at only by completing a full turn.
- **`Paradigms/`** the three independent axes a system can be placed on. Supervision ([[Supervised Learning]] through [[Unsupervised Learning]]), training regime ([[Batch Learning]] versus [[Online Learning]]), and representation ([[Instance-Based Learning]] versus [[Model-Based Learning]]). `Supervision/` also holds [[Zero-Shot Learning]] and [[Few-Shot Learning]], filed there as the nearest axis rather than as an exact fit, because the supervision axis sorts on what fraction of the training instances carry labels, a property of the training set as a whole, while those two sort on how many labelled examples exist for the classes you actually want predictions on, a property of one region of the label space. The two questions are independent, and a zero-shot or few-shot system is normally fitted by ordinary supervised learning while having nothing or almost nothing where it counts: what is short is coverage, not supervision. [[Zero-Shot Learning]] is the endpoint where the count is zero and a supplied description of each class has to carry the transfer the missing examples cannot, and [[Few-Shot Learning]] is the case where one to five labelled examples per class do exist and training runs over many small tasks, so that an unfamiliar label space costs no refitting.
- **`Tasks/`** what the system is asked to do: [[Classification]], [[Regression]], [[Clustering]], [[Dimensionality Reduction]], [[Anomaly Detection]], [[Novelty Detection]], [[Association Rule Learning]]. [[Classification]] itself now carries the tree of task types, and with it the claim that its own separation from [[Regression]] is a statement about how the problem was framed rather than about the data, since either task converts into the other: quantize a continuous target into buckets and the regressor is a classifier, cut a predicted score at a chosen threshold and the classifier was a scoring function all along. `Classification/` holds three things. The varieties of the first task, told apart by how many labels one instance may carry and how many values each label may take: [[Binary Classification]] for two exclusive classes, [[Multiclass Classification]] for one label out of three or more, [[Multilabel Classification]] for several yes-or-no labels carried at once, and [[Multioutput Classification]] for several targets each with classes of its own, which is the general case the other three are constrained versions of. The geometry every classifier's prediction reduces to whichever variety is in play, [[Decision Boundary]], the locus in feature space where the predicted label changes, which is not a target shape at all but is what any of the four amounts to once a model is fitted. And a decomposition of a label space rather than a fifth variety of one, [[Hierarchical Classification]], which takes a tree over the classes from the problem domain instead of discovering it, puts one classifier at each internal node deciding only among that node's own children, and makes a prediction a path from the root down to a leaf, so every decision is $b$-way instead of $K$-way and every node is fitted only on the rows whose label falls in its own subtree. What it costs is as exact as what it buys: $\frac{b^{d}-1}{b-1}$ fitted models instead of one, $d$ decisions per prediction instead of one, path accuracy decaying as $p^{d}$ in the depth, and an error near the root that nothing below can repair, since the subtree holding the true class is never entered at all.
- **`Models/`** the algorithm families, one folder per family. `Linear/` is the only family with methods under it, all of them the same machine seen from a different side. [[Linear Regression]] is the base case, a weighted sum of features, and the [[Normal Equation]] is its closed form rather than a model of its own, the one solve that reaches the least-squares optimum without iterating. [[Polynomial Regression]] is that same estimator handed powers and products of its columns, so the fit is curved while the model stays linear in its parameters. [[Ridge Regression]], [[Lasso Regression]] and [[Elastic Net Regression]] are the base case with a penalty on the weights added to the training objective, differing only in which [[Lp Norm]] is charged, which decides whether weights are shrunk, zeroed outright, or both. On the classification side [[Logistic Regression]] squashes the linear score into a probability, [[Softmax Regression]] lifts it to $K$ classes competing in one fit, and the [[Stochastic Gradient Descent Classifier]] is a linear classifier trained one instance at a time whose `loss` argument decides which of these linear models is actually being fitted. `Ensembles/` holds [[Ensemble Learning]], the idea rather than any method built on it.
- **`Objectives/`** what training optimizes: [[Performance Measure]] and its two sign conventions, [[Cost Function]] and [[Utility Function]]. A third level sits above both and is not a performance measure at all. [[Business Objective]] is the quantity the business is actually judged on, which the model neither optimizes nor reports, not differentiable and usually not measurable offline at all, being a property of what people did after they were served. What joins it to the reported measure is an assumption rather than a guarantee, that ranking two candidates by the held-out score ranks them the same way the business metric does, and that is a claim about one particular system and one particular pair of quantities, established on live traffic or not at all. The failure it predicts is the reason the experiment is worth its cost: every offline number can improve while the business metric fails to move or moves the wrong way, and nothing offline detects it, because no offline measurement observes that quantity. [[Decoupling Objectives]] is the question a folder of objectives has to answer once there is more than one of them at once, whether to combine them into a single weighted scalar before fitting or to fit one model per objective and combine the outputs at serving time, and it settles the question by counting. Changing a weight in the combined arrangement changes the training objective, so it changes the $\arg\min$, so it is a different model and a fresh fit, and exploring $k$ weightings costs $k$ fits; the decoupled arrangement fits $n$ models once and lets the weights enter afterwards as a scoring rule, so decoupling is the cheaper arrangement exactly when $k > n$, which is a crossover rather than a default. The combined arrangement pays a second price that is not about money, since minimizing a weighted sum with non-negative weights reaches only the convex hull of the Pareto frontier, so a trade-off lying in a non-convex region of it is available to the system and unreachable by any choice of weights. `Metrics/` holds the measures themselves, [[Root Mean Squared Error]] and [[Mean Absolute Error]] for regression, and for classification the [[Confusion Matrix]], which is the table the rest are read off. [[Accuracy]], [[Precision]], [[Recall]] and [[F1 Score]] are each a ratio of its cells, and [[Precision-Recall Tradeoff]] and [[ROC Curve]] are what you get by sweeping the decision threshold and taking a fresh pair of those ratios at every setting. [[Log Loss]] sits apart from all of those, scoring the predicted probability rather than the predicted label, and it is the rare measure that is the training objective and the reported metric at once.
- **`Optimization/`** the mechanics of fitting, which is to say the search through [[Parameter Space]] for the point that minimizes a [[Cost Function]]. [[Gradient Descent]] is the strategy nearly everything here is a variation on, and its three variants are told apart by one choice and no other, how many instances one gradient is computed on: all of them for [[Batch Gradient Descent]], one for [[Stochastic Gradient Descent]], a handful for [[Mini-Batch Gradient Descent]], and every difference in speed, in memory, in path regularity and in whether the thing converges at all follows from that single number. Around them sits the vocabulary that makes a fit legible rather than a black box: [[Learning Rate]] for how far one step travels, [[Learning Schedule]] for varying that over the run instead of fixing it, [[Epoch]] for the unit training length is counted in, and [[Tolerance]] for the number that lets an algorithm decide it has finished. [[Regularization]] is the other half of the folder and pulls in the opposite direction, constraining the fit on purpose so it explains the training data less freely, with [[Early Stopping]] as the instance that adds no penalty term at all and constrains only how far the optimizer is allowed to travel.
- **`Evaluation/`** estimating [[Generalization]] honestly: [[Testing Set]], [[Holdout Validation]], [[Cross-Validation]], [[Model Selection]], the two failures, [[Overfitting]] and [[Underfitting]], and [[Data Snooping Bias]], the way a test set quietly stops being one. [[Learning Curve]] is how the two failures are told apart rather than merely named, plotting training error and held-out error together so the gap between them is visible, and [[Bias-Variance Tradeoff]] is the decomposition that says why the two repairs point in opposite directions. [[Baseline Model]] sits at the front of all of it, the floor a candidate has to clear before it is a candidate at all, and [[Error Analysis]] at the back, reading which mistakes a model makes rather than how many, so the next thing to fix is chosen rather than guessed. `Hyperparameter Search/` automates the choosing, through [[Grid Search]] and [[Randomized Search]].
- **`Data/`** everything about the input. At the top sit [[Feature Engineering]], deciding what the model actually sees, [[Data Augmentation]], growing the training set with label-preserving transformations of what is already in it, and [[Open Data Repositories]], where a dataset comes from in the first place. `Challenges/` holds the seven ways data defeats a model, [[Class Imbalance]] among them, a label whose classes are not present in comparable numbers, so predicting the majority beats learning anything. `Sampling/` carves a dataset up: [[Random Sampling]], [[Stratified Sampling]], and the [[Random Seed]] that makes either one reproducible. `Exploration/` is the looking that comes before any fitting: [[Exploratory Data Analysis]], [[Correlation]], [[Skewed Data]]. `Preprocessing/` falls into three jobs. Fill the gaps, [[Missing Value Imputation]]. Turn categories into numbers, [[Ordinal Encoding]] and [[One-Hot Encoding]]. Put columns on comparable ranges, [[Feature Scaling]] and its two forms [[Min-Max Scaling]] and [[Standardization]], with [[Feature Distribution Transformation]] for columns that need reshaping first and [[Target Scaling]] for the label.
- **`Composition/`** the plumbing that combines estimators into one estimator, acting on estimators rather than on data. [[Scikit-Learn Estimator API]] is the contract the other six rest on, and its estimator, transformer and predictor taxonomy is what the `## Implementation` sections across the vault assume, not these six alone. [[Pipeline]] chains steps into a single fitted object and is what guarantees each step sees training folds only, [[Column Transformer]] routes named column subsets to their own branch and concatenates the results, and [[Custom Transformer]] is how an idea of your own earns the same interface, and so the same safety, as a built-in. The same job on a different axis is done by the meta-estimators, which wrap one estimator to give it a capability it does not natively have: [[One-versus-Rest]] and [[One-versus-One]] hand a two-class algorithm a multiclass target, the first by fitting one classifier per class and the second one per pair of classes, and [[Classifier Chain]] hands a single-label algorithm a multilabel one, by fitting a classifier per label in a fixed order and feeding each of them the labels already decided.
- **`Operations/`** what is asked of a model once it has shipped, which is a different question from how it was built. [[Production Machine Learning]] is the setting itself, a fitted model serving live traffic on behalf of somebody waiting on the answer, and nearly every priority inverts from the research one: several parties each want something different instead of one agreed score on a fixed benchmark, one prediction has to come back soon instead of one fit finishing soon, the data shifts while the fitted model stays as it was, and fairness and interpretability stop being things nobody scores. [[MLOps]] is the index for it, covering where a fitted model runs, whether it is still working today, and what to do when it stops, which is the practice `Knowledge/Systems Architecture/Operations/` describes for ordinary services applied to a system whose behaviour is learned from data rather than written by hand. [[Model Rot]] is the concern that has no counterpart there, the drift of the production distribution away from the training distribution, and the reason a shipped model has a maintenance cost at all: nothing about the model changes, its assumptions go stale underneath it. [[Continual Learning]] is the standing response to that decay, keeping a deployed model updated from data arriving after it shipped, carried by a scheduled retrain as readily as by an online fit, and inseparable from the research problem it meets at once, which is how to adapt to the newest data without destroying what the model already knew.

The mathematics these notes lean on sits outside this domain, in `Knowledge/Mathematics/`, indexed at [[Mathematics]], which lists its own contents. The machinery that stores, moves and serves the data sits outside it as well, in `Knowledge/Data Systems/`, indexed at [[Data Systems]], a subject that stands whether or not a model is ever fitted on anything it holds. The shape of the system all of it runs on sits outside it too, in `Knowledge/Systems Architecture/`, indexed at [[Systems Architecture]], which is about how work is spread across machines, who owns and operates them, and what is required of any system so arranged, rather than about what those machines hold: [[Reliability]], [[Scalability]] and [[Maintainability]] are stated there in the form that holds whatever a system stores, and their machine learning specialization, together with the fourth requirement that domain cannot own, adaptability, because stating it takes a fitted model in the sentence, is in [[Machine Learning Systems Design]].
